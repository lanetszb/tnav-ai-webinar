Short client briefing (~10 min). One line of framing: tNavigator 26.2 offers two ways to use AI, a fully local built-in assistant and external AI agents connected through the Local MCP Server. Today: the difference, then two working examples.
AI in tNavigator 26.2

Internal (AI Assistant) vs External (Local MCP Server) AI

Internal
1 · Built-in AI Assistant
What is itThe AI that comes inside tNavigator. Nothing extra to install.
What it can doAnswers questions, generates workflows, explains calculation logs.
Can it stay local?Yes, always. Works without internet. Your data never leaves your computer.
Internal
2 · AI Assistant + external model
What is itThe same AI Assistant, connected to a bigger AI model that you choose.
What it can doThe same tasks, with a stronger model.
Can it stay local?Yes, if the model runs on your own server (for example with Ollama). No, if you use a cloud model.
External
3 · AI agent via Local MCP Server
What is itAn outside AI agent (Claude, Codex, OpenCode) that drives tNavigator directly.
What it can doBuilds models, runs simulations, matches history, writes reports.
Can it stay local?Yes, if the agent uses a local model (OpenCode + Gemma). No, with cloud agents like Claude.
Simple rule: if the AI model runs on your own computers, your data stays with you. If it runs in the cloud, your data goes to the provider.
2
The core slide, kept simple. Three options, one question each: can it stay local? Option 1 is always local. Option 2 is local if the company hosts the model itself (Ollama). Option 3 is the most capable and can also be fully local with OpenCode + Gemma, as shown in the official release deck. Say the simple rule out loud.

The Local MCP Server: one protocol, the whole platform

What it lets an external agent do

Search tNavigator docs and the Workflow Python API
Open, create and copy tNavigator projects
Execute workflows with the full Model Designer API
Run calculations and read results back

Licenses for the Local MCP Server

1 × APISAPI Server
1 × APICAPI Client
1 × AIArtificial Intelligence
Ships as an installer component of tNavigator 26.2. Launch from the GUI: Settings → Options → AI Server → Launch Local MCP Server. No administrator privileges required.

That's the capability on a slide. Two working examples follow: building a model from scratch, and engineer-level analysis with dashboards.

3
The protocol is open: any compatible MCP client connects. Examples use Claude and Codex; the official release deck shows the same thing driven by OpenCode with a local Gemma model, which keeps even the external route fully on-premises.

AI in tNavigator 26.2

AI agent at work: match, forecast, report

Using BLACK_OIL_DEMO, the agent ran 616 simulations: differential-evolution history matching, a 200-run sensitivity study, segmented per-well DCA, and a 10-year forecast. The interactive dashboards below show cumulative field error falling from 54% to 7.3% for water and from 12% to 1.6% for oil, with measured BHP included in the objective.

5
Be transparent: the campaign was pre-computed (~1 h of simulations). Scroll the embedded dashboards: objective function 65.1 → 2.77, per-well water-cut panels, DCA panels with one Arps fit per decline cycle. The agent produced the dashboards themselves as HTML reports. Key message: AI does the work, the engineer supervises and decides.
Takeaways

The simulator now speaks AI

  • Internal: the built-in AI Assistant ships with tNavigator and keeps every byte on your hardware.
  • External: the Local MCP Server connects any compatible AI agent, which can search, build, run, match, forecast and report.
  • Engineering judgment stays human: the agent executes; the engineer reviews and decides.
6
Close on the pairing: internal for data safety and everyday assistance, external for autonomous heavy lifting. Both come out of the standard 26.2 installer.
